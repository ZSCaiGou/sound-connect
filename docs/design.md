# sound-connect 设计方案

## 定位

个人自用的 Windows 桌面工具：把音效和你正在听的音乐送进语音软件，让队友听见。
不对外分发，因此本方案不处理驱动签名、自动更新、安装包体积和跨平台打包。

## 核心约束

Chromium 的系统回环采集只能拿到**系统默认播放设备**的整路声音，无法指定"只采某个程序"。
如果直接采默认设备（也就是你耳机上的声音），队友的声音会从 Discord 播放到同一设备、被回环采走再传回去，他们会听见自己的延迟回声。

解决办法是在设备层面把"要分享的声音"和"你和队友说话的声音"隔开。

## 数据通路

```text
QQ音乐 / 浏览器 ──→ CABLE-A(虚拟线，设为系统默认播放设备)
                        │
                        └─(回环采集)──┐
                                      ├──→ 混音 ──┬──→ CABLE-B ──→ Discord 输入 ──→ 队友
麦克风 ───────────────────────────────┤            │
                                      │            └──→ 物理耳机 ──→ 你自己听
音效文件 ─────────────────────────────┘
```

- 输入：麦克风 + CABLE-A 的系统回环（音乐）+ 音效文件
- 输出：CABLE-B（队友）+ 物理耳机（本地监听），两路音量独立
- 音乐和音效是两条独立通道，放着歌按音效不会把歌打断

## 设备与配置前提

第一次运行需要完成五件事，这些会做进启动引导里：

1. 系统默认播放设备 → CABLE-A
2. Discord 输入设备 → CABLE-B
3. Discord 播放设备 → 物理耳机（漏掉这步就会出现回声）
4. 戴耳机（音乐经我们转手，外放会被麦克风捡到，队友听到两遍）
5. 关掉 Discord 的降噪、回声消除和自动增益（否则持续的音乐会被当背景噪声削掉）

需要两个虚拟设备。VoiceMeeter 免费版装完会提供 VAIO 和 AUX 两个，正好够用；VB-CABLE 免费版只有一个。

## 已知副作用

- 默认设备切成虚拟线后，游戏声音、系统提示音、B 站视频也会一起进语音。打游戏时需要在游戏里单独把输出指回物理设备。
- 你自己的音乐是绕经本地监听的，会晚几十毫秒。纯听歌无所谓，一边放歌一边看视频会有音画偏差。
- 队友听到的音质上限由语音软件决定。Discord 语音是窄码率的单声道链路，音乐会有明显压缩感，这个改不了。

## 备选路线

如果纯 JS 这条路走不通（Electron 的回环采集 API 在版本间变过几次），退到原生方案：写一个小的 WASAPI 采集模块，用进程级回环只抓 QQ 音乐那个进程。更优雅——不用改系统默认设备，你自己听歌零延迟——但要写 C++ 或 C# 加构建链，工作量高一个量级，不优先。

另一条兜底路线是完全不采集：让 VoiceMeeter 当混音台，音乐和麦克风都由它混合，我们的程序只往虚拟设备播音效。最稳、延迟最低，但音乐路由要用户自己配，程序也变薄了。

## 代码结构

```text
src/main/index.ts              窗口、全局热键、回环采集授权、剪贴板、设置持久化
src/preload/index.ts           contextBridge 暴露的 IPC 接口
src/renderer/src/audio/
  types.ts                     通道、设备、电平、日志的类型
  devices.ts                   设备枚举与虚拟设备识别
  loopback.ts                  系统回环采集（新接口 + 旧接口兜底）
  engine.ts                    音频引擎：混音图、双输出、音效池、电平与诊断
src/renderer/src/spike/        验证原型界面（阶段一，验收后拆除）
```

## 验证清单

原型要回答的问题，全部答完再写正式界面：

1. 回环到底能不能采到虚拟线上的声音（默认设备设为 CABLE-A 时）
2. 采集流能不能关掉回声消除、降噪和自动增益（`track.getSettings()` 的实测值）
3. 端到端延迟是多少（Discord 自带回声测试 + 麦克风本地监听体感）
4. 双输出能不能同时工作（一路 CABLE-B，一路物理耳机，音量独立）
5. 连续跑十分钟会不会断流、爆音或漂移（每秒采样电平 + 静音计数）

## 阶段划分

- 阶段一：验证原型，只做能回答上面五个问题的最小界面
- 阶段二：音频引擎正式化、设置持久化、设备引导
- 阶段三：音效库（扫描、分组、搜索）、全局热键、音效编辑
- 阶段四：打磨——托盘、开机自启、配置导入导出
